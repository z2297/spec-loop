Autonomous spec-driven delivery pipeline

How Spec-Loop turns a request into shipped, verified work

One feature request goes in. It is decomposed into small, independently shippable pieces that are built, reviewed, and quality-gated in parallel — then assembled onto a single branch and verified as a whole. The team is asked to decide only twice: what's genuinely ambiguous up front, and how to ship at the end.

The workflow

request → delivery
1

Intake & decompose

Turn a request into a vetted plan.

The request is restated and broken into small, independent slices. Before any effort is spent, an adversarial review panel (the "Iron Council") pressure-tests the idea for scope, risk, and soundness. Only genuine ambiguities are raised — once, together, up front.

Human decision · only if ambiguousAdversarial vetting
2

Set up one integration branch

Everything will converge on a single branch.

A dedicated branch is created off main, named for the work. Every slice will merge here and nowhere else. main is never touched until you approve at the end.

Single branchmain untouched
3

Schedule work in parallel waves

Independent work runs at once; dependencies wait their turn.

Slices that don't depend on each other build concurrently in isolated workspaces; the rest are ordered so nothing collides. More throughput, no interference.

Parallel & isolatedDependency-aware
4

Build each slice

Plan → build test-first → review → auto-fix → quality gate → verify.

Each slice is planned, its plan re-vetted by the Council, then implemented test-first. Code review runs at a depth matched to the slice's risk, findings are auto-fixed, and the result must clear an objective quality bar and a fresh test run. A slice that turns out too large splits itself back into the plan — automatically.

Fully autonomousReview + quality gate↻ self-splits if too large
5

Integrate — one slice at a time

Finished work merges serially, race-free.

A single controller — not the parallel workers — merges each verified slice onto the one branch, one after another, then runs the full test suite after every wave. Conflicts and drift surface early, while they're cheap to fix.

Controller-owned mergeSuite runs each wave
6

Integration gate

Verify the assembled whole, not just the parts.

Once everything has landed, the complete test suite plus a cross-slice review confirm the pieces work together — catching contract drift a per-slice check can't see. Any failure spins up a small remediation task and re-verifies, still without human contact.

Whole-system verification↻ auto-remediated
7

Publish — your call

Push as a feature branch, or merge onto main.

The run ends by asking how to ship the finished, verified branch: open it as a feature branch (optionally a pull request) or merge it onto main. Nothing is pushed and main is never modified without your explicit choice.
